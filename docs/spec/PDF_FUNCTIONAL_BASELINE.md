# IntroGenerator：PDF機能との対応確認

添付された『Scratch イントロエンジン完全講座』全115ページを読み、本文と図で確認できる機能を32項目に整理しました。

**最低要件は「ユーザーが作れる表現・調整できる内容」です。** PDFの内部アルゴリズムを複製する要件ではありません。20回の残像描画、400点の曲線、黄金比による配置、固有の変数名、特定のCostume名、空欄の扱いをそのまま採用する必要はありません。

従来の18章の設計を土台に、機能の不足や編集データで表現できない箇所を補いました。Webは引き続き、同じsb3を入力にする独立エンジンです。

## 今回補ったこと

- 4点に固定されないBezier曲線の編集データ。
- 柔らかい文字残像と鮮明な本体を併用するEffect。Cameraを含む動きへの対応。
- 曲線の端点装飾、曲線沿いの光・影の独立した調整。
- 複数のEffectの影をまとめて本体の背面へ置く設定。
- 軸対称・点対称配置と、内容の向きを保つ複製。
- 任意の強さのPower easingとHSVによる色調整。

これは新機能を全て専用Runtimeへ足す変更ではありません。契約1.2でAuthoring保存形式を補完し、Scratch側のIGRT/1.1のTables・Opcode・汎用Moduleは維持します。

## 機能の合格条件

各機能について、Editorで設定→値を変更→Undo/Redo→保存・再読込→sb3へ出力→ScratchとWebで再生、を通して機能が失われないことを確認します。見た目だけを1枚の完成動画として取り込めても、元の曲線・文字・Effectの設定を編集できなければEditor対応とは判定しません。

組合せ試験は以下を最低限とします。

| 試験 | 合格条件 |
|---|---|
| 文字＋Camera＋残像 | Cameraのみの移動、文字のみの移動、両方の移動の全てで残像を調整できる。鮮明な本体を残せる |
| 背景＋拍ごとの緩急 | 模様が連続して流れ、BPM・区間速度を変えても編集内容が保持される |
| 粒子＋繰り返し＋色変化 | 広がり、回転、分布、見た目を独立して変更でき、seek後も配置が安定する |
| 連番＋複数方向＋影 | 同時に角度展開でき、全ての影が本体の背面になる |
| 自由曲線＋流れる区間＋端点装飾 | 制御点数を増減でき、表示位置・長さを動かしても端点の装飾が追従する |
| 曲線の光＋対称配置＋Camera | 元曲線の編集が両側へ反映され、線・光・端点の太さを整合させて拡大できる |
| 全機能の合成 | 背景→粒子→影→Effect本体→文字等の指定順を両Runtimeで維持する |

## PDFの実装と異なってよいもの

| PDF内の方法 | 引き継ぐ機能 |
|---|---|
| 一時ListのSet/Add | 基準値と複数の変化を時間範囲付きで重ねる |
| 固定回数の残像Stamp | 長さ・強さ・柔らかさを調整できる動きの残像 |
| 曲線を400点へ分割 | 自由曲線と、その上を進む線・光・装飾 |
| 黄金比の配置 | 偏りが少なく安定した粒子の広がり |
| 全Shadow→全Baseの処理 | 複数の影が各本体の背面にまとまる重なり方 |
| Miror変数の符号変更 | 対称配置と反対側への複製 |
| Costume名から連番を選択 | 任意の素材列を時間に合わせて再生する |

PDFには説明とコードで境界条件が違う箇所や、フレーム経過に依存する処理があります。それらを不具合互換として移植しません。既存設計の任意時刻seek、安定したID、明示的な時間・座標系を使って必要な機能を提供します。

## 1.3での続き

FUNCTIONAL_SPECIFICATION.mdで32機能の操作と期待結果、元要求の18機能群、境界での見え方を確定しました。BPM変更時の固定基準と放射Particleの保存情報をIGAUTHOR/1.3へ補っています。再生ABIはIGRT/1.1です。

## 確認状態

115ページすべてに機能対応を付けました。機械可読のページ索引と各機能の合格条件は`pdf-feature-coverage.json`にあります。これは資料の網羅確認です。このPDFだけでは元作品のCostume・元sb3・完成映像を揃えた実行比較はできておらず、元作品との画素一致を確認したという意味ではありません。

製品Editor／Compiler／Scratch Runtime／Web Rendererの実装・実機確認は未実施です。今回の検査結果は`verification/results.json`と`verification/feature-results.json`に分け、Schema・数式の確認と製品の機能試験を区別します。
